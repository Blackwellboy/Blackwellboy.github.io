Blackwellboy / Tools

Checks you can run before blaming the model.

The tools are built around one idea: make the serving path observable. Start with the smallest check that can falsify your current explanation, then go deeper only if it survives.

Start here

The shortest path from “this model looks wrong” to a useful diagnosis.

Registry

model-serving-minefield

A registry of serving and configuration failures that can make a healthy model look broken or make a bad measurement look convincing. It currently contains 116 entries across 9 categories: evaluation, memory, quantization, reasoning, routing, runtime, template, tools, versioning.

Each entry starts with the symptom, then the mechanism, the check that catches it and the fix. Evidence status is explicit: reproduced here, reported by others, or under test.

Fastest triage

The Core 12

The small set to check first when you do not yet know where the failure lives. These are the traps chosen because they are cheap to test, easy to mistake for model behaviour, and have already cost time across more than one setup.

Endpoint preflight

minefield-doctor

A stdlib-only Python preflight for OpenAI-compatible endpoints. It runs 19 read-only checks covering reasoning fields, templates, thinking control, tool parsing and output ceilings, and reports anything it could not check instead of pretending it passed.

A clean doctor run is not a clean bill of health; it is a fast first pass over the failure classes visible from the API surface.

Template forensics

preflight_template.py

Renders a marked multi-turn conversation through your own path so you can inspect what the model actually receives at turn N. This catches history stripping, role/template mutations and reasoning loss that request-shaped endpoint checks can miss.

Reference & integrity

Deeper material for reproducing, porting and keeping claims consistent over time.

Operational guides

Playbooks and stack pages

7 ordered playbooks for jobs such as publishing an A/B, debugging reasoning loss, porting a harness, investigating long context and reading a soak. Alongside them are 11 stack pages covering hf-transformers, llama.cpp, lm-studio, MLX, Ollama, sglang, tabbyapi, tensorrt-llm, text-generation-inference, text-generation-webui and vLLM.

Self-checking research

The integrity layer

A claim ledger records corrections and retractions, and propagation checks look for superseded phrasing across public surfaces. Mutation tests deliberately reintroduce known failures so the checks prove they can still catch the thing they were built for.

Worked example

Laguna S 2.1 operators guide

A model-specific example of the same method end to end: serving configuration, thinking control, tool format and quantisation floor, with each claim linked back to the study directory holding the raw data.
